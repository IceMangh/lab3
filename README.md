# GRAPH / LAB

Веб-интерфейс лабораторной работы № 3: доска для редактирования графа, раскраска, кратчайшие пути, минимальный остов и компоненты связности. Чёрно-белые светлая и тёмная темы, пошаговый просмотр и упругая сетка, реагирующая на курсор. Шрифты Manrope и IBM Plex Mono загружаются локально и поддерживают кириллицу.

## Запуск

Из папки `lab3`:

```sh
./run.sh
```

Откройте **http://127.0.0.1:8000**. Скрипт установит зависимости фронтенда при первом запуске, соберёт его и запустит локальный сервер. Нужны Node.js 20.19+ (или 22.12+), npm, Python 3.10+ и компилятор C++20 (`clang++` / `g++`). Отдельный Python-пакет не требуется. Другой порт: `./run.sh --port 8080`.

Ручной запуск:

```sh
cd web
npm ci
npm run build
cd ..
python3 server.py
```

Для разработки запустите `python3 server.py` из корня, а во втором терминале — `cd web && npm run dev`. Vite открывается на **http://127.0.0.1:5173** и перенаправляет `/api` на C++-сервер с портом 8000. После изменений C++ сервер автоматически пересобирает адаптер при следующем запросе.

## Работа с графом

- Солнце и луна в верхней строке переключают светлую и тёмную темы. Выбор сохраняется в браузере; граф, камера и текущий шаг продолжают работать в прежнем состоянии. Цвета в результатах раскраски и компонент обозначают группы вершин.
- Курсор выбирает и перемещает вершины. «+» добавляет вершину в выбранном месте. Связь создаётся последовательным выбором двух вершин. Корзина удаляет вершины или рёбра.
- Перетаскивание фона, инструмент руки или пробел с перетаскиванием перемещают доску. Колесо масштабирует её к курсору. Вершины можно переносить за пределы исходной области. Кнопка подгонки показывает граф целиком, соседняя кнопка упорядочивает вершины.
- Панель параметров сворачивается кнопкой в верхнем правом углу; её границу можно перетаскивать. Режим развёрнутой доски закрывается по Escape.
- Сетка с тонкими линиями, опорными крестиками и узлами деформируется возле курсора и плавно возвращается в исходное состояние. Она движется вместе с доской и меняет детализацию при масштабировании. Кнопка сетки отключает её. Системная настройка уменьшенного движения отключает эффект. При неподвижном курсоре анимация останавливается.
- Вес существующего ребра меняется после нажатия на него: в боковой панели введите значение и нажмите Enter или переведите фокус. Вес новой связи задаётся в панели, когда выбор снят.
- В панели параметров задайте количество вершин (0–100) и нажмите «Сгенерировать граф». «Новый граф» открывает дополнительные настройки: плотность, цикл, вершины без рёбер, готовый пример, ручной список рёбер и импорт JSON. Поле количества вершин доступно сразу.
- Выберите задачу и нажмите «Запустить алгоритм». В поиске пути доступны Дейкстра и BFS; старт и цель выбираются в панели или через выбранную вершину.
- «Компоненты связности» показывает реальные шаги DFS: посещение вершины, переход по ребру, возврат и завершение компоненты. Подсвечиваются текущая вершина, ребро перехода и стек обхода. Состав и число найденных компонент растут по мере просмотра. Изолированная вершина считается отдельной компонентой. В этом режиме генератор создаёт несвязный тестовый граф с числом компонент до трёх; в диалоге «Новый граф» этот шаблон называется «Несвязный».
- Воспроизведение, стрелки, ползунок и скорость позволяют изучить решение в обе стороны. Для компонент воспроизводится запись обхода C++; для остальных задач последовательно раскрывается готовый результат.
- Экспорт сохраняет граф и результат в JSON, данные и время в CSV или текущее изображение в SVG. JSON можно импортировать обратно. Граф автоматически сохраняется в `localStorage` браузера.

Поддерживаются 0–100 вершин и целочисленные веса от −10000 до 10000. Вершины нумеруются с 0. Повторяющиеся рёбра отклоняются. Раскраска учитывает соседство по входящим и исходящим дугам. Петля делает правильную раскраску невозможной. Для Краскала нужен неориентированный граф, для Дейкстры — неотрицательные веса. BFS считает рёбра независимо от весов. При отсутствии пути выводится `∞`. Для несвязного графа Краскал строит минимальный остовный лес. Жадная раскраска не гарантирует минимальное число цветов.

## Электроснабжение района

Откройте вкладку «Электроснабжение» или адрес `http://127.0.0.1:8000/#power`. Один объект всегда служит подстанцией. Укажите число домов и нажмите «Применить количество домов» для ручного ввода или «Сгенерировать», чтобы построить связный район с кварталами, улицами и ЛЭП между соседними объектами. Можно менять названия объектов, добавлять и удалять допустимые кабели и редактировать их стоимость. Поддерживаются до 99 домов и 5000 соединений с целой стоимостью от 0 до 2 147 483 647 у. е.

Редактор использует доску лаборатории. Нажмите «+» и кликните по доске, чтобы поставить дом. Инструмент связи соединяет два объекта со стоимостью из поля «Стоимость». Дома и подстанцию можно перемещать вместе с их кабелями. «Рассчитать сеть» строит минимальную сеть. Доска показывает кабели по возрастанию стоимости. При равной цене сначала показаны кабели из рассчитанного остова. Каждый шаг показывает добавление кабеля или пропуск из-за цикла, текущие затраты и дома, уже связанные с подстанцией. Под картой можно поставить просмотр на паузу, сменить скорость или перейти к любому шагу. Переключатель «Выбранные» скрывает прочие соединения. Результат содержит итоговую стоимость и время вызова Краскала. Если район несвязный, интерфейс перечисляет дома, до которых нет пути от подстанции. Кнопка «Пример» возвращает район из условия, где три кабеля стоят 9 у. е.

Задача реализована в `PowerSupply.h` поверх существующих `Graph`, `Kruskal` и `BFS`. Фронтенд режима находится в `web/src/power/`. Тесты в `tests/test_power_supply.py` проверяют пример, некорректные входные данные и оптимальность на малых графах полным перебором.

## Связь с кодом лабы

```text
React / SVG → POST /api/solve → server.py → C++ bridge → Graph + Algorithms
```

В C++ граф создаётся через `Graph::Create`. При некорректных входных данных операции графа и алгоритмы возвращают `std::nullopt`. Адаптер `web/backend/bridge.cpp` вызывает `BFS`, `Dijkstra`, `GreedyColoring`, `Kruskal` и `ConnectedComponents` из `Algorithms.h`, затем сериализует результаты. Алгоритмы на JavaScript не дублируются. Поиск компонент в интерфейсе доступен для неориентированного графа.

Для неориентированного графа `Kruskal` возвращает остов или лес в `std::optional<Graph>` и использует существующие `Edge` и `DynamicArray`. Рёбра сортируются выбором. Каждая вершина хранит номер своей компоненты; при соединении двух компонент их номера объединяются обычным проходом по массиву. Такая учебная реализация проще для чтения, её сложность — `O(E² + V²)`. Общий вес и число компонент вычисляет веб-адаптер.

Сохраняется существующая зависимость `Graph.h` от `../atd/DynamicArray.h`: соседняя папка `atd` должна присутствовать. C++-адаптер собирается в игнорируемую `web/.build/`. Фронтенд находится в `web/src/`; фон сетки рисуется Canvas 2D, граф — SVG. Сервер работает только на `127.0.0.1` и предназначен для локальной лабы.

## Проверки

```sh
python3 -m unittest discover -s tests -v
npm --prefix web test
npm --prefix web run build
python3 server.py --check
```

Проверки адаптера сравнивают расстояния с независимой реализацией, раскраску — с ограничением соседства, а вес остова — с полным перебором маленьких графов. Также проверяются направленные и несвязные сети, нулевые и отрицательные веса, пустой граф, некорректные вершины и устаревший формат ввода. Тесты фронтенд-модели покрывают удаление и перенумерацию вершин, импорт, экспорт и генерацию графа.
